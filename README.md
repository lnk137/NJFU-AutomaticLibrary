## 启动与使用

项目已整体迁移到 `/Users/a0000/项目/图书馆自动预约`。开发报告位于 `development/outputs/`，测试日志、截图和回退证据位于 `development/work/`；这些含本地诊断资料的目录不纳入 Git。原软件与开发目录保留兼容符号链接，不占用第二套环境或数据库。

双击 `Start-NJFU.command`，或运行：

```bash
bash "/Users/a0000/项目/图书馆自动预约/Start-NJFU.command"
```

打开 <http://127.0.0.1:5003>，保留启动终端。按 `Ctrl+C` 会停止网页、调度器和本项目启动的 MongoDB，账号和历史保留。重复启动会复用已运行的本机服务；端口被其他软件占用时会报错，不会终止其他程序。

1. 打开网页先登录。学生输入学号和学校统一身份认证密码（与 `uia.njfu.edu.cn` 相同）；必须同时通过学校验证和管理员的学号准入。不需要 VPN 密码。学校密码在运行节点加密保存，支持本人开启的后台计划；双机托管账号的凭据分别保存在 Mac 和 Ubuntu，不上传协调服务器。
2. 学生只查看和操作自己的账号、计划和预约结果。每个账号独立选择首选/备选座位、使用时段和学校放号提交时间；每周计划按实际使用日匹配星期。
3. 管理员切换到“管理员”入口，使用 `root` 和初始化时设置的独立密码。登录后默认打开“运行看板”，并提供“用户管理”和“管理员”页。全部执行历史、新增学校账号、管理记录在“管理员”页中；看板明细也可进入全部历史。后台不显示学校密码或管理员密码。
4. 停用学号会使学生会话失效并关闭未来定时计划，保留历史和学校已有预约；重新授权不会自动开启计划。退出网页登录或8小时会话过期也不会停止已开启的计划。
5. 未保存修改会提示放弃或继续编辑；配置冲突时保留草稿。“学校记录”查询学校当前记录，查询失败保留上次成功结果并标出时间。

新版网页使用同一套真实接口和会话：电脑为双栏计划/运行看板，iPad自适应分栏，手机使用底部导航与底部弹窗。座位目录不代表实时空位；放号日期与实际使用日期分别展示。切换和关闭弹窗会保护未应用修改，所有学校密码只在当前输入框短暂保留，不回显、不写浏览器持久存储。

### 管理后台

在本机以 root 登录后打开 <http://127.0.0.1:5003/#/pages/admin/admin>。运行看板显示所选放号日的成功、失败、跳过、待核实及未完成任务，下一轮各账号的放号时间、实际使用日期、首选和备选座位，以及异常明细。下一轮“本地计划检查通过”仅说明保存配置合规，学校登录在临近放号时验证，不能据此判断预约成功。

自动图表包括每日结果趋势、各账号首次请求相对放号时刻的延迟、每日请求耗时 P50/P95，可查看7、14或30天并切换定时/当天任务。统计按北京时间放号日归属；成功率为成功数除以成功、失败、跳过三者总数，待核实及未完成不计入分母。首次请求延迟只取第一次尝试，提前发起显示负值；缺失计时显示“无数据”，不会填成0。耗时分位数附有效请求样本数。

看板每30秒自动刷新，只在页面可见且仍为 root 时轮询；刷新失败保留上次结果并标出过期状态。所有统计仅读取本机已保存数据，不触发学校登录、查询或预约。单次最多统计5000条历史记录，超限或数据库超时明确报错，不显示不完整统计。

“用户管理”支持按学号、姓名、备注搜索和按状态筛选；统计轮询不覆盖备注草稿，离开前提示未保存修改。停用前确认具体学号，停用仅关闭其未来计划并使会话失效，不取消学校已接受的预约。管理日志可搜索最近100条操作。以上管理功能仅本机 root 可见，公网继续仅开放学生入口。

本机状态在 `.local-data/power/`（目录0700、文件0600），不含学校密码。原生wake-only helper及安装标记在 `/Library/Application Support/NJFUAutoLib/`，系统任务为 `/Library/LaunchDaemons/org.njfu.autolib.wake.plist`；用户任务为 `~/Library/LaunchAgents/org.njfu.autolib.power.plist`。原生组件只读取固定开关，使用独立owner维护单个未来唤醒事件，不以root执行项目或Python代码。

### 首次管理员初始化

已有管理员时无需再次执行。新安装须在项目根目录运行以下命令，按不回显的提示输入两次管理员密码；重复执行会拒绝覆盖原密码。每个首批学号使用一个 `--allow`：

```bash
.venv/bin/python -B local_admin.py --allow YOUR_STUDENT_ID
```

管理员密码只保存为 scrypt 哈希；学校密码继续使用独立 AES-GCM 密钥。会话 Cookie 为 HttpOnly、SameSite=Strict，服务端只保存凭据摘要，8小时过期；登录有失败频率限制。本机管理入口仅供回环访问；公网学生入口按下方专用转发模式配置，管理员仍只在本机使用。

默认入口 `Start-NJFU.command` 保持真实预约总开关关闭，仅允许登录、保存配置和查询，不会提交、取消预约或执行迟到保护。“保存计划”不表示学校已预约成功。关闭网页不停止后台；关闭启动终端、电脑休眠或断网会影响执行。

根据[官方使用帮助](https://libseat.njfu.edu.cn/#/ic/userhelp)，新计划已预填次日预约、每天07:00放号和全天时段：07:30–22:00，周五按实际使用日自动提前到20:00。切换为“每周预约”时，七天时段均已填好，周五07:30–20:00，其余07:30–22:00；可清空某天两个时间跳过该日。每次需为2–15小时；开始后30分钟内签到。已有手工计划保持原值；“高级设置”可恢复07:00，“使用时段”可选择学校全天后保存。官方日历可查看未来日期，不表示该日已经开放预约。

“预约计划”点击时段行的“修改”，可见“学校全天 / 自定义”选项，以及上午、下午、晚间快捷预设；页面显示当前配置下一次的放号日期和实际使用时段，未保存的编辑会明确标注。周五20:00上限由后台统一保证，适用于全天、自定义每天、自定义每周及当天预检；晚于20:00的结束时间自动截短，更早结束会保留。调整后仍须满足至少2小时，否则提示重新选择，不会提交不合规时段。

每日日程的自定义时段保存时也检查周五：例如19:00–22:00会因周五实际只有19:00–20:00而拒绝保存；18:00–22:00可保存，周五实际为18:00–20:00。仅需非周五的晚间计划可使用“每周预约”并关闭周五。既有配置不自动重写；不合规旧配置会提示管理员核对，不拖累其他账号。

### 个人表单导入（仅本机 root）

在 root“运行看板”下载个人填写模板，发到群里。每个人只填写自己的一份，再私发给管理员。模板左边列项目，右边填写姓名、学号、学校密码、预约类型、首选/备选座位及使用时间；预约类型选择“生成定时计划”或“当天一次预约”。管理员收到后拖入或选择 XLSX、CSV，每份一人、最多32 KiB；多人名单整份拒绝，不会先验证或保存其中的人。旧版只有一位用户的文件仍可导入。学号和密码按文本填写，不支持公式、宏、附件或外部工作簿链接。

定时计划的“使用日期”留空，“每周日期”留空表示每天，填写1,3,5表示周一、三、五；放号时间留空为07:00:00。当天一次预约填写北京时间今天的日期，每周日期和放号时间留空，选择尚未开始的整点/半点时段。座位可填目录中的完整编号或ID；周五按实际闭馆时间显示。

导入后自动验证这一位用户。验证通过的新账号直接保存为正式账号，不开启计划；已经保存的账号、凭据和运行计划在确认前保持原样。root 核对申请人的预约信息后，点一次“确认这份预约”：定时计划保存并开启，当天预约立即执行。验证失败直接显示原因，没有勾选或再次确认。这套审阅只针对表单提交的预约，普通用户原有操作不变。

后台保留导入状态，关闭弹窗或请求超时后可重新打开、刷新状态；不会自动重交预约。审阅有效期为验证完成后15分钟。放号准备期间暂不验证/执行导入；并发更新、权限停用、过期或学校重复预约会阻止相应行。原有日期例外、收藏和历史保留，当天预约不会替换定时计划。已确认批次若因服务重启中断，只显示已处理结果和待核对状态，不自动重放；先核对账号及学校记录。导入记录及未完成的加密凭据最多保留24小时。学生及公网不能读取模板或导入记录。

表单当天预约与普通预约共用忙碌重试间隔：首次立即提交，后续同时满足相邻请求发起至少1.2秒、前次响应完成后至少1秒，两者取较晚时刻，再查询学校记录；已出现有效回执就停止重交。等待期间权限、执行开关、放号保护和30秒尝试预算仍持续生效。

### 公网收件的独立连接地址

遇到代理假DNS导致公网收件握手超时时，可在本机项目数据目录的 `inbox/route.json` 保存仅当前用户可读的配置，例如 `{"schema":1,"origin":"https://njfuautolib.duckdns.org:45581","connect_ip":"183.66.27.20"}`，权限0600。重启后台后仅收件连接使用该地址；学校登录、预约连接、系统DNS和代理不变。

连接仍使用原域名的Host、TLS SNI、证书主机名和CA校验，不关闭TLS验证，不跟随重定向，不在网络错误后自动重发POST。未配置时沿用原连接；配置无效时仅暂停收件，本机计划继续运行。公网服务器IP迁移后需更新此项目配置并核验；不根据未验证的DNS响应自动替换。原有配置版本、有效期、认证和落库后确认机制保持生效。

### 时钟保护与有限自适应恢复

时钟变化会先暂停发送，再在放号静默窗口以外核对时间。学校网页时间失效或不可用时，使用 Apple、阿里云和 Cloudflare 三个固定 NTP 来源中的两个一致结果交叉核验。NTP 报文检查随机回显、同步状态、延迟和偏差，但不是 NTS 加密认证。软件只检查时间，不修改系统时钟。

自动恢复每轮最多失败6次，间隔为1、3、10、30、60秒，之后冷却60秒再开始新一轮。唤醒可提醒重新检查，但不绕过冷却、权限或校时；DNS卡住时探测等待有上限，不拖住退出。独立时钟监测在恢复I/O期间继续工作，重新授权前检查时钟和最新放号窗口；管理员暂停、账本损坏或身份异常不会被自动解除。已错过的任务不补交，已发送的任务不重放。管理员运行状态及本机电源快照保留本进程最近的故障、校时结果与重试状态；首次时钟故障也写入后台日志。

### 内部撞座提醒（仅本机 root）

root 的“运行看板”会检查未来7天尚未放号的定时计划。不同账号在同一天、同一座位的使用时段重叠时，显示日期、座位、重叠时段和双方账号；首选重叠和含备选的可能重叠分别标注。检测使用实际计划，包含每周安排、跳过日期、单日调整及周五时段；尚未应用的收藏和分组不参与。

这项功能只提醒，由管理员自行决定是否调整，不自动改计划、不提交预约、不查询学校空位。默认展示3条，可展开；最多返回50条，超过时显示“50+”。配置或权限异常而未参与检查的计划会明确计数。历史统计日期筛选不改变这项未来检查；学校已有预约、当天手动预约及已到放号时间的计划不在本项范围内。学生和公网不能读取这些管理信息。

### 个人收藏、偏好分组和自定义标签

在普通计划、当天预约或单日调整的选座窗口，可切换“全部座位 / 我的收藏 / 偏好分组”。点座位旁星号收藏；在“我的收藏”中自行填写标签，也可按标签搜索。每人最多100个收藏，每个收藏最多5个标签、每个标签最多20个字符，不预填任何标签。

把当前首选和备选顺序存成自己的分组后，可编辑名称、调整顺序或删除；最多20组，每组1–5个不同座位，名称最多40个字符。点击“使用此组”只填入当前选座草稿，仍需点击原有“应用”和保存计划，或保存本次日期调整。分组后续修改、取消收藏或删除分组都不改变已经保存的计划及预约。目录缺失座位会保留显示，但不能静默删掉该座位后应用分组。

收藏与分组保存在账号独立字段并使用独立版本检查，不改变预约计划版本，不占用预约账号锁，也不触发学校登录、查询或提交。另一设备已修改时会提示重新读取，并保留当前编辑输入；核对最新内容后再保存。目录中的座位失效时，可以单独取消收藏、删除分组，或打开旧分组后用当前选座替换。离线时可以选用上次同步的收藏和分组，修改需等待执行电脑在线；学生只操作自己的数据，root 仍可管理当前选中的账号，不增加审批步骤。

### 临时日期调整

在“预约计划”的“临时调整”中，可直接跳过下次自动预约、按日期范围请假，或只修改某一天的使用时段及首选/备选座位。“只改某天”也能为原本不预约的星期增加一次，执行仍受账号权限、基本计划开启状态和真实预约总开关控制。日期均指北京时间的实际使用日，放号日期仍提前一天。

日期调整独立保存在账号的 `date_exceptions` 字段，保留原有每天/每周计划；调整日期过去后按原安排继续。单日调整可保留并编辑全部1–7个时段及各段座位顺序，支持添加和删除；保存后作为当天完整安排的快照，不随以后基本计划修改而变化。双机托管账号仍只支持单段，页面会提前提示并限制多段保存，不会截断内容。草稿遇到其他页面更新会要求重新读取，避免覆盖。双机准备及执行期间暂不能修改对应的使用日；其他远期日期仍按自己的放号时间单独检查。使用现有学校时间规则，包括周五截短及至少2小时。每个账号最多保留366个日期，连续请假合并显示；可点击“恢复原计划”移除对应设置。移除已过期设置不会补交预约，也不会取消学校已有预约。

新增或改写只能针对尚未放号、尚未执行的日期。放号前3秒至放号后30秒暂不接受日期编辑，为数据库写入留出预算并保护正在执行的任务，跨午夜的放号也适用；已有任务结果与学校回执保留。保存使用账号版本检查，不会覆盖另一页面的新配置；学生直接编辑本人账号，无需 root 审批。离线入口可查看上次同步的信息，日期编辑需等待执行电脑在线，原有离线基本计划同步流程保持不变。

计划页、首页下次预约摘要和本机 root 下一轮预览均按日期调整计算；长时间请假不会误报成无效每周计划。

### 当天分段预约

1. 使用下面的正式入口启动，学生可在“预约计划”面板的“高级设置”下方点击“当天分段预约”，也可在“我的预约”点击“当天预约”；管理员进入具体账号计划后点击“当天预约 · 手动预检”。
2. 在当天弹窗添加时段，每段分别选择首选与备选座位。例如09:00–12:00坐A、14:00–18:00坐B、18:00–20:00坐C。一次可填写1–7段，每段最多5个座位；时间可以首尾相接，不能重叠，也不能与学校已有预约重叠。
3. 默认从北京时间今天的下一整点或半点预填2小时，可以自行修改。每段须满足学校开放时间及至少2小时，周五最晚20:00。当天已无合法未来时段时显示空状态，停止新增和预检，仍可查看已有结果；已编辑的草稿保留。点击“检查全部时段”只查询并校验，不提交；摘要显示实际使用时段，最多有效2分钟。返回修改或切换账号后需重新检查。
4. 核对后点击“确认提交这 N 段预约”，只确认一次，后台按时间顺序逐段检查、预约，界面分别显示每段结果。也可关闭弹窗后重新打开查看；“刷新本地进度”只读原批次，不会重交。有待核实段时优先点击“核对学校记录”，显式查询学校记录后刷新原批次，核实前不能另起批次。核对失败保留已有结果和草稿。每段仍有独立“当天手动”历史和学校回执。

明确的座位忙碌或占用已按共享策略耗尽有限候选后，可以继续下一段；限流、未知拒绝、结果待核实、查询失败或执行校验失效时停止后续时段，并标明“未提交”。已成功的预约保留。确认请求超时后保留原批次编号，只查询其结果；服务重启不会重放未完成的批次。在“学校记录”刷新并核实成功后，批次内已处理段也会更新结果，后段仍保持未提交。临近定时准备和执行窗口时暂不启动当天批次。批次异常后若数据库暂不可用，后台独立重试结果收尾，恢复后标明剩余段未提交，不重新执行批次。批次完成后，本机管理员的账号历史会自动刷新。

当天操作不修改每天、每周计划、日期例外及个人收藏，也不取消学校已有预约。重复确认只返回原批次；当天预约数量等限制仍由学校检查。默认只查询入口允许预检，但禁止真实确认。原单段当天接口和个人表单中的当天一次预约保留兼容。

### 定时多时段与预约日历

在“预约计划”的“多个时段”中，为每天或每周各天添加独立时段与首选/备选座位。每段至少2小时、最多5个有序座位，一天最多7段；允许首尾相接，不允许重叠，周五最晚20:00。应用后再保存并开启。旧单时段计划保留原设置；日期跳过作用于当天全部时段，“只改某天”用该次单日设置替换全天安排。

现有单时段计划继续使用当前执行器。原生模式下，新多时段批次使用受同一权限、时钟和恢复保护的有界Python后备队列；原生已有任务优先，不接管已登记的发送资格。

多时段按时间顺序逐段提交，每段有独立执行记录。普通座位忙碌的有限尝试耗尽后可继续；结果不明、限流、未知拒绝或权限/版本变化会停止后段并显示未提交。已处理的使用日不会因更换时段编号或放号时间自动重开一轮。

“我的预约／执行记录”新增月历和周历，按实际使用日期查看计划、临时跳过、学校确认、失败、待核实及取消结果。管理员可选择具体账号，学生只看本人。日历只读已保存数据，较早回执标明更新时间；顶部刷新同时刷新日历，页面可见时约每15–20秒更新一次。“临时调整”进入原计划页并完整回填目标日的全部时段。双机等待选机、准备就绪及未发送与结果待确认分别显示；双机同步异常显示服务需检查。

### 邮件通知与主动取消

在“我的／管理员”打开“邮件通知”，填写收件邮箱、获取并输入验证码，再分别开启结果通知与使用前提醒。默认提前30分钟，可设1–1440分钟；未开启时不发送。每个已确认时段分别提醒，取消成功后停止该段提醒。首次开启不补发旧结果；执行电脑须保持后台运行、在线，睡眠期间错过的提醒不补发。

使用前提醒邮件中的“取消预约”按钮可直接取消对应的具体预约，无需登录或再次确认；链接绑定收件邮箱、账号凭据版本和学校回执。双机结果有严格匹配的学校记录时也提供同样按钮；只有回执摘要而没有具体学校记录时提供查询入口，不伪造取消目标。放号保护或暂停等明确尚未提交的临时拦截可稍后重新点击原邮件；未知结果只核对状态，不重复取消。网页学校记录中的主动取消仍需核对并确认。成功以学校接受并回查核实为准，超时保留待核实状态，重开仅查询，不重复取消。其他时段及定时计划保留。学校决定当前是否允许取消；仅查询启动模式不允许真实取消。

管理员发件配置见 [邮件配置说明](docs/mail-notifications.md)。发信服务默认关闭，本地模拟测试不代表已接通真实邮箱。

### 开启自动预约

1. 如果默认后台正在运行，先在原启动终端按 `Ctrl+C` 停止；账号、座位和历史保留。
2. 双击 `Start-NJFU-Live.command`，或在终端执行：

   ```bash
   bash "/Users/a0000/项目/图书馆自动预约/Start-NJFU-Live.command"
   ```

3. 学生打开“预约计划”；管理员在“用户管理”进入具体账号的“计划与记录”。确认座位与时段，点击“保存并开启定时”。多个账号分别开启；“仅保存”不会把关闭的计划开启。
4. 保持终端、电脑和校园网运行，避免电脑休眠。按默认计划，后台在放号前3分钟准备登录、前约1.5秒读取公钥并为首选及备选座位完成独立加密准备，07:00发起次日预约；结果在“总览”和“学校记录”查看。

正式入口允许发送真实预约请求。已开启的账号计划会保留，重启正式入口后继续执行；新账号仍需单独开启。默认入口与正式入口的模式不同时会报错提示停止原后台，不会悄悄切换。`NJFU_ALLOW_LIVE` 等环境变量不会开启执行，只有显式 `--enable-live-booking` 启动参数可以打开总开关。

停止某个账号可点击“关闭定时计划”；停止整个后台可在启动终端按 `Ctrl+C`。恢复只查询模式时，停止正式后台并改用 `Start-NJFU.command`。停止调度不会取消学校已经接受的预约。

macOS的调度校时和预热载荷有效期使用包含睡眠时长的 `mach_continuous_time`，正常睡眠唤醒后不会因两种时钟进度不同而锁住后续计划。真正的系统时间跳变超过两秒仍暂停提交，记录首次错误；总览会突出显示“自动预约已暂停”和原因，学生公网入口也能看到。请核对系统时间后重启后台恢复。电脑需要在放号时保持唤醒；睡过原执行窗口的任务不补交，已有跳过记录也不因重启重放。

提交速度优化只提前进行只读请求和本地运算，不提前发送预约。正常只读预热仍在提前4.5秒启动，并在提前1.5秒附近刷新不能覆盖放号时刻的参数。原生定时流程对已知的临时网络、HTTP和会话参数故障，允许最多4轮预热；每轮完成后至少间隔100毫秒，剩余时间必须超过250毫秒才开始下一轮，同一账号不重叠预热。身份、权限、计划版本和未知错误不自动重试。连接预热结束后再次检查参数有效期；参数仍只在准备完成后2秒内有效、绑定当前任务/会话/座位且只消费一次。原生ARM登记继续保留放号前50毫秒截止，不延长有效期，也不补交已过期任务。手动预约、表单当天预约和Python回退保留各自原有提交保护。提前预热不是学校响应速度的保证。

首发前保留任务领取及首个座位的一次持久化写入；已存在的相同任务直接读取，避免重复插入/更新。请求发送前读取最新执行权限后，再检查最新时间与执行保护。计时版本2从HTTP客户端调用处记录`request_started_at`，另外保存`guard_ms`和`request_finished_at`；`request_ms`不再包含最终本地权限检查。旧记录不重写，缺少`timing_version=2`的历史仍为旧口径，跨版本耗时不能直接作为提速比较。这些时间都不能证明学校收到请求的时刻。学校拥堵和网络仍影响结果，模拟延迟不代表真实成功率。原有自定义触发时间不会自动更改。

首发获取已登录会话时，复用本次执行在账号锁内刚核验的账号信息，避免重复读取账号和准入表。仅复用仍有效、身份及凭据版本匹配的已有会话；缺失、过期、版本变化或强制刷新仍重新读取并验证。授权不跨执行缓存，发送前的最新权限、时间、时钟检查及持久领取写入均保留。

定时任务的 `scheduler_timings` 保存提前登录、只读预热和提交阶段的排队、账号锁等待、学校登录/预约验证、参数准备、连接预热与执行起止时间；每轮状态、固定错误码、错误发生环节和尝试历史按白名单保存，每阶段历史最多11条，不保存原始异常正文、密码、Cookie、Token或请求体。准备失败和窗口截止时记录停止原因与正在等待的阶段；已开始的只读任务结束后异步补全耗时。调度线程产生的诊断由独立诊断线程保存，原生提交后的诊断继续由结果收集线程记录；写入失败不改变预约结果，旧任务不补造计时。2026-10-21的隔离慢公钥实验和2026-11-02的临时故障复现均属于工程验收，不能作为历史故障唯一原因或真实学校速度的证明。

后台临时读取或循环异常会显示自动恢复提示，下一次轮询成功后清除，不再误锁时钟。MongoDB单次操作预算为2秒，连接、socket和连接池等待均有上限；计划轮询或截止调度超过5秒未成功完成时，会显示阻塞告警并取消“就绪”标记，恢复后自动清除。真正的系统时间跳变仍保留暂停保护。执行器即使只短暂检测到时钟异常，也会保持暂停并在可信时间核验后自动尝试恢复；无法核验时继续暂停。单个账号的登录锁、计划错误或准备异常独立处理；清理数据库写入不持有调度全局锁。提前登录或只读预约检查的网络/HTTP临时错误最多再尝试10次，按1、3、10、20秒逐步延长，其后间隔30秒；临近放号时保留准备机会，且始终受计划版本、权限和原30秒窗口限制。密码、验证码和身份错误不重试；登录结果不确定时不重复提交密码。任务一旦进入真实提交阶段，继续使用原有结果核实与有限忙碌恢复规则，历史失败任务不补交。

提前登录维持4个并发，预热和提交各最多并行20个账号，线程按任务需要创建；第21个等待对应阶段空位。离线收件的账号同步也使用20个并发上限。20是各关键阶段的线程池上限，并非整个进程的线程总数；更新后下次启动生效。root运行看板显示当前实际的提交并发上限；已有任务数、放号时间、每账号尝试次数和重试限制保持不变。

## 公网网页，本机校园网执行

给同学的入口：<https://njfuautolib.duckdns.org:45581/>。同学无需安装 Tailscale。先由管理员在本机授权其学号，再由其自己在网页输入学校密码、选座并保存计划或开启定时。

- 网页经雨云NAT的45581→8443、HTTPS网关和加密反向通道访问本机。学校认证、原密码的AES-GCM密文、密钥、实际计划与预约执行仍在本机；服务器仅保存离线密码校验哈希、必要的账号/结果缓存和配置收件，不保存学校原密码或本机解密密钥。
- 优先通过执行电脑实时学校认证。仅当执行端连接确实不可用时，已授权、曾通过学校认证且本机已保存密码的用户可用上次成功认证的密码登录离线配置模式。学校明确拒绝、验证码、协议错误和学校网络超时均不会降级放行。离线会话只开放本人缓存和计划收件，学校查询、更新密码及当天真实预约须重新实时登录。
- 到学校放号时间，已经保存并开启的计划由本机定时器直接请求学校，不临时等待公网派单。当前已核实的手册规则为每天北京时间07:00开放次日预约；07:30是开始使用时间。学校特别通知和规则变化仍须核对，程序不会自行抓取新通知改动规则。
- 公网只开放学生登录；`root`及管理接口只在 <http://127.0.0.1:5003/> 使用。浏览器会话通过HTTPS传输并使用Secure/HttpOnly/SameSite Cookie，仍执行学号准入和本人数据隔离。

重启电脑后双击 `Start-NJFU-Public.command`（允许已开启计划在放号时提交），并保持电脑开机、不合盖休眠、连接校园网。该入口复用项目 `.venv` 中获授权安装的 `waitress==3.0.2`，不使用Flask开发服务承接公网流量。重复打开同模式会提示已运行，不会启动第二个调度器。要停止整个公网与预约后台，双击 `Stop-NJFU-Public.command`；学校已接受的预约不会被取消。默认本机只查询入口与公网正式入口模式不同，切换前先停止旧后台。

通道断开会自动重连；已落库的定时计划继续由本机执行。本项目的HTTPS入口监听8443，两个SSH转发端口15003/15004只监听服务器回环；专用账号不能执行Shell或转发其他端口。本机保持回环5003，不直接开放数据库或本机网卡端口。

### 离线收件与自动同步

离线保存先显示“待同步，尚未生效”，原本机计划继续运行。页面默认只显示简短状态，点“说明”展开同步规则和版本；没有新提交时不显示待同步提示。管理员的同步区域优先显示待处理账号，正常账号收在“同步详情”，唤醒组件的控制按钮在“运行详情与设置”。

后台启动、睡眠唤醒及网络恢复后自动同步；运行中持续核对版本，使用本机加密保存的密码重新认证学校，通过准入、时间和版本校验后原子落库，收到本机确认才显示“已生效”。学校预约是否成功仍以学校回执为准。

配置使用独立提交编号、云端版本、原本机版本及有期限租约；重复投递不重复修改，过期或冲突配置不覆盖本机新数据。同一账号有未确认收件时先等待处理，不静默替换。落库后确认丢失会通过本机凭据恢复；授权变化后的旧消息仅允许核对已落库结果，不能重新执行。进入放号准备或账号正在准备预约时，新配置顺延本轮结束后同步，不补交本轮预约。

本机root看板新增执行端心跳、最后同步和版本核对时间、当前待同步/失败账号数、认证/快照异常、云端与本机生效版本及计划检查状态。单账号慢登录、快照或确认异常不阻塞其他账号；预约提交并发上限维持20。放号前提高版本核对频率，开抢附近暂停新增同步I/O；已确认的本机计划不依赖公网临时派单。

离线授权快照最长24小时、会话最长8小时、待同步配置最长48小时。电脑完全离线时无法即时获知本机刚做的权限变更；重连后按最新授权和凭据世代重新核验。已知学校拒绝必须由新的学校认证成功清除，管理备注变更不会清除拒绝。

本机配置位于`.local-data/inbox/`，仅当前用户可读；缺失配置时保持原运行方式，配置错误会提示但不关闭原调度。公网网关由独立低权限`njfu-inbox.service`运行，使用项目独立runtime和私有SQLite；15005/15006分别承接公网转发与同步控制，仅监听服务器回环。部署、Nginx、源码和静态资源都有对应回退证据，数据库及既有历史不因部署而重建。

证书由服务器Certbot签发并由专用systemd计时器检查续期，DNS校验凭据仅root可读。受服务器出口网络限制，证书/DuckDNS访问经证书专用通道借用本机网络，端到端TLS校验保持开启；该出口仅允许证书机构和DuckDNS的443端口，不承载学校预约请求。续期时本机公网连接也需在线；本机已有HTTPS代理若启用且可用，将用于证书机构访问。证书申请或续期失败会保留原证书，可从服务器项目服务日志检查。

开发新增验证：公网入口权限、Secure Cookie、禁止远程管理员、受限SSH、离线503提示与自动重连、真实CAS登录与只读查询、证书续期dry-run；没有据此宣称已完成正式放号抢座验收。

- 普通座位提交已按当前官网改为 `/ic-web/reserve/seat`，使用官网 RSA/AES 加密格式；放号前检查预约验证码要求，读取新公钥并预先生成本任务首选和备选的独立请求载荷，每个载荷使用新的随机AES密钥、仅消费一次，且不超过两秒有效期。缓存仍绑定账号、计划版本、日期、时段、学校身份和会话；失效时重新获取公钥。提交时再次核对执行窗口；要求人工验证码时停止自动提交。
- 对已观察到的精确回复 `code=1` 且消息为“当前设备正在被预约，请稍后重试”或“设备在该时间段内已被预约”执行有限恢复，不将所有 `code=1` 当成可重试。明确占用的座位仅在本任务内跳过，继续其他备选；忙碌座位保留有限重试机会，按实际提交次数计算总上限。首次请求不增加等待；每次忙碌重试同时满足“相邻请求发起至少1.2秒”和“前次响应完成后至少1秒”，取较晚时刻，不把两段间隔相加。慢响应只能消耗发起间隔，不能抵扣响应后的1秒冷却；缺少可信HTTP耗时时保守等待完整1.2秒。等待期间分片检查执行保护，随后完整查询使用日学校记录；定时任务仍须成功且为空，当天手动任务也可在记录身份、状态及时段均已核实且与本段不冲突时继续。`retry_check`保存`pacing_policy=dual_interval_v1`及两条间隔，等待时间不混入HTTP的`request_ms`。这组参数来自2026-10-25本人授权低峰实测后的工程余量选择，学校未公布固定限频阈值，不能保证覆盖高峰或所有计数窗口；明确“请求频繁”仍停止后续提交。最多两轮、每座位两次、总计六次的上限与原30秒尝试预算保持。备选优先消费有效期内已准备的独立载荷，过期重新获取，不延长2秒有效期。发现本任务已尝试座位的精确有效回执即确认成功；定时任务发现其他记录、当天手动任务发现冲突或无法验证的记录，以及查询失败或结果不确定时均停止重交。
- 候选座位按配置优先顺序轮换，最多两轮；单座位最多2次、全任务最多6次，保留原放号后30秒截止以及当天预检过期、开始时间等限制。每次后续提交重新检查计划版本、开启状态、准入、时钟和执行开关。未知拒绝、已接收但未核实、超时不自动继续；已完成的历史失败任务不会因更新而补交。每次忙碌尝试的 `retry_check` 保存目标间隔`spacing_ms`、前次HTTP耗时`previous_request_ms`、实际睡眠`wait_ms`、含保护读取的等待阶段`pacing_elapsed_ms`，以及随后查询状态和查询耗时；不混入`request_ms`。开抢前后50毫秒内以1毫秒间隔检查调度，其余时间维持10毫秒。该恢复流程已用隔离学校接口测试，未额外提交真实预约，不据此保证成功率。
- 默认本机入口只监听回环地址；手机和校外访问使用上方经HTTPS验证的公网学生入口。
