# 管理员运行看板设计

状态：2026-10-24 用户已确认，按本设计在当前对话实施。用户另授权优化现有root管理体验，保留权限边界与所有数据。

## 目标与约束

让管理员打开页面即可回答：今天是否按计划完成、哪些同学需要处理、下一轮哪些计划已配置、时间花在哪里。只展示本机已保存证据，不增加学校请求，不提交/补交/取消预约，不修改账号、权限、计划或历史。复用 Vue/Uni-app、Flask、MongoDB 和现有绿色界面，不安装依赖。管理员仍只允许在本机 root 使用，学生与公网不能读取全体用户统计。

## 已选择的方案

- 完整运行看板（用户已选）：结果、下一轮计划、异常、三张自动图表和账号状态；保留原用户管理与审计入口。能够集中判断运行情况，工作量高于仅增加数字。
- 轻量统计区：原布局加数字和两张图，改动小，但仍需跨页核对下一轮与异常；未选。

## 界面布局

1. 顶部：本机调度/时钟/执行开关、数据更新时间；日期选择默认北京时间今天，历史范围7/14/30天默认14，任务类型默认定时，可切换全部或当天手动。
2. 今日结果：已记录任务数、已核实成功、失败、跳过、待核对、准备/执行中；可点击状态筛选明细。结束任务成功占比=成功/(成功+失败+跳过)，明确分母和样本数，待核对/未结束不塞入失败或成功；无分母显示“—”。
3. 下一轮：按各人真实触发时间计算下一次放号与使用日、实际时段、首选及备选座位；汇总开启计划、通过本地检查、需处理数量。周五按现有20:00政策预览。文案为“本地计划检查通过，学校登录待临近放号验证”，不承诺学校会话永久有效或一定抢到。
4. 异常清单：后台告警、计划校验异常及所选日期的失败/跳过/待核对任务；显示原始安全原因、学号/姓名、时刻和查看账号入口。自动分类只能基于明确的记录字段，不推断缺失的根因。
5. 三张图：每日结果堆叠柱状图、本机首次请求发起延迟条形图、请求往返耗时趋势（中位数/P95）。点击/触摸查看日期、样本数和精确数值。缺数据时保留空态，不画成0。
6. 账号状态表：授权/停用、是否完成学校登录保存、计划开关、最近网页登录/学校验证时间、下一轮时间、座位、检查结果。保留学号搜索和查看计划/记录入口。用户管理与审计保留独立区域，电脑表格、手机卡片。

## 统计口径

- 所有日期使用 Asia/Shanghai；图表与今日结果按 spec.due_at 的放号日分组，使用日 target_date 单列。手动与定时按 spec.kind 区分，旧缺省 kind 视为定时。
- 成功仅使用已核实的持久化 success；提交已接收、uncertain、skipped 均不算成功。没有记录的日期显示“无执行记录”，不推断全部失败。统计从服务端范围内完整记录生成，不从前端100条分页拼接。
- 开抢延迟仅针对定时任务，只用 attempts[0].timings.request_started_at 减 due_at，首个尝试缺失或无效时不以第二次重试替代；明确 sent=false 的尝试不视为已发起请求。它代表本机开始请求，不代表学校收到请求；不以 execution_started_at 或任务结束时间冒充请求时间。负值保留并标为提前发起。
- 请求往返使用 attempts.timings.request_ms，包含网络和学校处理；不称为纯学校内部耗时。只取有限且非负的有效数字；缺失值与异常数字不参与均值/分位数，明确有效样本数。P50/P95采用nearest-rank，少量样本P95通常等于最大值，页面说明样本有限。
- 登录、账号锁等待、预热、线程排队等现有 scheduler_timings 在明细中展示；旧记录不补造计时。每个任务的多次尝试保留顺序，首发延迟与重试耗时不能混淆。
- 准入人数、已保存账号、开启计划分别展示，不能当成当前在线人数。已保存登录凭据不等于已验证当前学校会话。

## 实现边界

- 新增只读 GET /api/local/admin/dashboard，先验证本机 root，再读取明确投影的账号/准入/执行记录并聚合。参数 date、days(7/14/30)、kind(all/scheduled/manual)严格校验。响应不含凭据、哈希、token、Cookie或密钥。日期范围查询使用字段投影、maxTimeMS=1000及5001条探测上限；最多完整处理5000条任务。超时或超过上限明确返回不可用/范围过大并保留旧数据，不输出被截断的统计。异常明细最多50条并标明总数，账号表支持前端筛选。GET不会创建索引。若性能验证表明需索引，另列可审查的加载步骤后执行。
- 独立 dashboard.py 负责口径和下一轮计算，复用 validate_plan/resolve_run；不调用学校客户端、调度执行或写入生产集合。
- 新增独立 Vue 看板组件及轻量 SVG 图表，复用现有依赖。避免修改学生页面、公共主题和任务外 design-preview/ 原型。
- 看板每30秒自动更新只读数据，可手动刷新；只允许一个在途统计请求；页面隐藏/退出root时停止，旧响应不得覆盖新筛选或新会话。刷新失败保留上次结果并显示时间/过期提示。用户备注编辑与准入列表不随统计轮询被重置。旧请求的成功、失败、loading变化和全局认证事件都检查会话代际；延迟401不得清除后来登录的新会话。为此给API请求的认证事件增加代际保护，401不再附带会清除新会话的Cookie删除响应，显式退出仍照常清除Cookie。
- 仅页面打开时聚合，不创建新定时任务、自动化、服务或学校轮询；不在开抢提交线程计算图表。

## 验证与加载

1. 独立随机端口MongoDB和虚构学校边界：日期跨日、手动/定时筛选、各种状态、超过100条历史、缺失/NaN/负值计时、少样本分位数、周五时段、无计划/未授权/坏旧配置、缺省kind旧记录、首个尝试缺失但第二个有效、超5000条拒绝截断统计及查询超时。断言读取前后集合内容一致且学校客户端零调用。
2. API认证：未登录401、学生403、公网root403；响应无敏感字段。
3. 实际Vue组件与纯函数测试：空态、错误保留、筛选竞争、退出/切账号清空、有效样本数和图表标签；旧管理员统计未返回→退出→学生登录→旧401返回，不能清除学生新会话。
4. 电脑和手机浏览器检查：图表读数/筛选、无横向溢出、用户管理功能保留、只读操作不修改计划与历史。
5. 全量后端/前端测试及隔离H5构建；无执行中任务且距放号大于10分钟时加载。保留源码基线、当前前端回退和必要验收证据，核对生产账号/计划/历史摘要不变。

## 验收标准

管理员可以在一页看到所选日结果、下一轮本地计划状态、需处理账号和三张真实数据图；所有数字可追溯到已有记录。学生入口和原预约流程不变，额外真实预约与学校请求均为0。缺少历史细节时明确无数据，不将健康检查或配置开启冒充学校预约成功。
