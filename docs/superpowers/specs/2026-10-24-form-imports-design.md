# Reviewed form imports

## Goal
Local root downloads a simple Excel template, receives a filled XLSX/CSV, drops it in the root page, and sees automatic per-row account/booking validation. Each row selects either a scheduled plan or one booking today. One whole-file confirmation performs all passing rows, with no checkboxes. Only imported requests require this review; normal users' existing flows are unchanged.

## File and review
Columns: 姓名或备注, 学号, 学校密码, 预约类型, 首选座位, 备选座位, 开始时间, 结束时间, 使用日期, 每周日期, 放号时间. Scheduled rows use blank weekdays for daily, or 1–7 separated by commas for a common weekly interval; default trigger 07:00:00. Today rows require today's explicit YYYY-MM-DD date and ignore no extra settings silently. Use seat IDs or unambiguous catalog names; up to five ordered seats. One row per student per file, at most 50 people and 32 KiB. Reject formulas, macros, external workbook links, XML entities, oversized expanded ZIPs and malformed headers. Passwords remain text and never appear in previews or logs.

Reuse installed openpyxl 3.1.5 for reading XLSX and stdlib CSV. Author and ship a static blank XLSX template with the spreadsheet tool; no new installation or environment. File transport uses the existing authenticated JSON/CSRF boundary with base64 content, never a new public upload.

## Account and execution semantics
- Valid new accounts become formal saved encrypted accounts after school login, with root-authorized access and no active plan. Explicitly disabled access is never re-enabled by an import. Existing accounts validate with an independent login client, leaving saved credentials/revision/plan untouched until confirmation.
- Preserve the file's requested configuration as an encrypted, expiring batch in a dedicated collection. Validation and confirmation use one on-demand worker, not the scheduler. API requests return quickly; root can reopen a recent batch, avoiding timeout/re-upload duplicate actions.
- Before root confirmation: zero scheduled plan updates or school submissions. Show actual normalized plan/today date, Friday-capped times, ordered seats and per-row errors. For today rows, validate with existing TodayBookingService local rules and read school records using the verified temporary client; show overlap/uncertainty failures before review.
- On confirmation, claim the batch atomically once. Recheck permission, expiry, account revision, busy state and the release quiet window. Each passing scheduled row updates only its selected account, atomically recording credentials/plan/import marker with CAS; retain date exceptions/favorites/history and synchronize authentication-success observers only after commit. Today rows retain the scheduled plan and use existing local validation, live/clock gates, bounded candidate order and school receipt matching in an import-only executor. Independent authentication/queries and payload preparation happen without booking locks; short non-blocking locks only commit and claim. Preserve the ordinary 30-second attempt budget and bind the file expiry/release guard through the final school submission callback. No row-level confirmation.
- Repeated upload request IDs or confirmation requests return existing status/results; no second execution. Claim first, persist each result, and never automatically replay a confirmation interrupted by process failure. Restart marks only unfinished import batches interrupted, retains processed receipts, and requires inspection/re-import. No booking backfill.
- Authentication is outside booking locks; short commit locks are non-blocking. Defer/reject work in the 180-second preparation/40-second post-release window around all enabled/requested triggers, including midnight. Recheck after slow login/reads. No changes to scheduler, reservation algorithm, ordinary account APIs, saved plans outside confirmed rows, or prior features.
- Encrypt credential payloads with the existing vault; drop payload after completion and use a dedicated 24-hour TTL for retained pending batch payloads. Safe views contain only requested plan/account/status/results, no passwords, tokens or envelopes.

## UI and validation
One compact root-only import launcher and dialog: template download, drop/select file, automatic validation, readable row summaries/errors, a single confirmation button and persisted results/recent batches. Retain only the pending upload ID, never file/password content, across lost responses and navigation; recovery queries that ID without re-sending a mutation. Session/role guards prevent stale cross-login results. Poll only active import jobs while visible. Students/public roots cannot access routes or template.
